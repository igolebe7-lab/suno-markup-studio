## Полный каталог справки

[Открыть автономную копию справочника](reference.html). Рабочее приложение также содержит отдельный экран справочника с одной статьёй на экране. Данные `reference-data.json` и `sources.json` используются его сборкой; автономный HTML остаётся для редакционной проверки.

Каждая запись имеет музыкальное объяснение, место применения, ссылки на настройки, примеры и ограничения. Статьи сгруппированы по категориям; внутри каждой страницы есть оглавление и якоря для всех тегов. **Все 407 существующих тегов покрыты; прослушиванием не проверен ни один.** У 12 новых кандидатов подготовлены отдельные данные для дальнейшей редакции.

Примеры не являются чужими текстами песен или результатами успешных генераций. Настройки объясняют, как наше приложение формирует текст, а не скрытый протокол Suno. Музыкальный смысл написан редакционно; источники подтверждают только явно указанную область. Точная поддержка произвольного дескриптора не выводится из общей рекламы модели.

## Для реализации

- [reference-data.json](reference-data.json): 407 статей, 12 черновиков кандидатов, 27 определений параметров.
- [coverage.json](coverage.json): проверяемый отчёт покрытия.
- `content.mjs`: редактируемые индивидуальные значения музыкальных терминов и объяснения настроек.
- `build-reference.mjs`: воспроизводимая сборка справки из текущего каталога и редакционного материала, с проверками ID/источников/примеров. Не обновляет `apps/`.

Из корня репозитория, Node с поддержкой strip-types (использован Node 25.9.0):

```bash
node docs/suno-2026-09-29/build-reference.mjs
node docs/suno-2026-09-29/build-reference.mjs --check
```

Статус `editorial-draft-audio-untested` намеренный. Экран приложения показывает это ограничение и использует только действующие 407 статей; 12 кандидатов не опубликованы как рабочие теги. Существующий `tagKnowledge.ts` оставлен для обратной совместимости, но экран справочника теперь читает подготовленные данные напрямую.

## Проверка пакета

Сборка и `--check` выполнены. Проверены 3166 внутренних Markdown-ссылок и якорей, уникальность ID, полнота параметров, корректность JSON и дат источников. В Chromium/Playwright проверены 1440×900 и 390×844: поиск, пустой результат, категории, 407/419 записей, отдельные статьи, reload, прямые ссылки с пробелами в ID, неизвестный ID и возврат к списку на телефоне. Горизонтального переполнения и ошибок консоли не обнаружено. Копирование проверялось с подменённым Clipboard API; разрешение реального системного буфера зависит от браузера, предусмотрено выделение текста при отказе. Browser plugin со skill `browser` в сессии отсутствовал, использован установленный Playwright.

Для подключения P0 выполняются `npm test`, `npm run build`, `npm run e2e` на приложении. Проверка production на собственном VPS и аудиогенераций описывается отдельно в отчёте о выпуске.

## Чего здесь нет

Нет запуска Suno, расхода кредитов, передачи пользовательских текстов внешней модели, новых зависимостей или изменений секретов. Изменение проекта при переносе старых исключений требует явного подтверждения пользователя. Релиз приложения на VPS требует отдельного commit/push, Linux-сборки и безопасного переключения только Suno-сервиса.
